# Аудиомодем HEX — демо-приложение

Консольная передача файлов звуком (динамик -> микрофон) с адаптацией
скорости под уровень шума. Итог лабораторных 1–7.

## Запуск

```bat
python app/modem.py
```

Меню:

```
1) Передать файл
2) Принять файл
3) Показать принятые файлы
4) Замерить фоновый шум
5) Loopback-тест без железа (цифровой канал)
6) Проверка связи (есть ли приёмник рядом)
0) Выход
```

- **Передать** — покажет файлы из `app/files_to_send/` (выбор номером),
  `d` — системный диалог выбора файла, либо путь вручную. Туда же можно
  просто класть свои txt — они появятся в списке.
  Перед передачей модем проверяет связь: handshake повторяется до 5 раз,
  и если приёмник молчит — передача отменяется с подсказкой
  (так сразу видно, что на другом конце никто не слушает).
- **Принять** — реальный эфир (sounddevice), полудуплекс.
- **Показать принятые** — листинг `app/received/`.
- **Замерить шум** — 3 с записи тишины, вывод RMS и «справочного» SNR,
  подсказка рекомендуемого режима.
- **Loopback** — два потока в одном процессе, канал = numpy + AWGN
  с заданным SNR. Проверка всего стека без колонок/микрофона.
- **Проверка связи** — «пинг» приёмника: шлёт probe-кадр до 3 раз;
  если на другом устройстве запущен п.2, приходит ответ «на связи».

> **Важно:** протокол двусторонний (handshake + подтверждение каждого кадра).
> Передача «на диктофон телефона» — это запись звука, а не приём: телефон
> не отвечает на handshake. Нужен второй ПК/ноут с запущенным п.2
> (микрофон слушает колонки первого).

## Как это работает

Протокол сессии (полудуплекс, stop-and-wait ARQ):

```
TX                                  RX
 |---- HANDSHAKE (FSK) ------------>|  имя|размер|md5|кадров
 |                                   |  замер SNR по handshake
 |<---- ACK(режим) (FSK) -----------|  pick_mode(snr)
 |---- DATA кадры (mode) ---------->|  RS(10)+interleave(8), CRC32
 |<---- ACK / SWITCH (FSK) ---------|  пробник каждые 8 кадров
 |---- EOF (FSK) ------------------>|  сверка MD5, запись файла
```

Кадр: `type(1) | seq(1) | payload(32)` → RS(44,34) → перемежение 8 →
пакет с преамбулой + CRC32.

### Режимы и пороги SNR (калиброваны замерами, не теорией)

| Режим  | Модуляция      | Порог, дБ | Бит/с (ном.) |
|--------|----------------|-----------|--------------|
| FSK    | 2-FSK Goertzel | страховка | ~100         |
| QPSK   | OFDM QAM-4     | >= 12     | ~25k         |
| 16QAM  | OFDM QAM-16    | >= 18     | ~50k         |
| 64QAM  | OFDM QAM-64    | >= 28     | ~75k         |

### Адаптация под шум (три уровня)

1. **Старт** — RX меряет SNR на handshake и диктует режим в ACK.
2. **Live-пробник** — каждые `PROBE_EVERY=8` кадров RX переоценивает SNR
   (в эфире — шум в хвосте окна записи, где сигнала уже нет) и шлёт
   `SWITCH`, если текущий режим вне диапазона (гистерезис 3 дБ).
3. **Fallback-деградация** — если канал рухнул резко и ни один кадр не
   проходит (нет ACK за 6 попыток), TX сам понижает режим по цепочке
   64QAM→16QAM→QPSK→FSK; RX ловит это по FSK-декоду кадра. Работает
   даже при полной потере связности в OFDM-режиме.

### Пары (тест «несколько пар одновременно»)

Каждая пара работает на своих FSK-тонах (handshake/ACK/EOF):

| Пара | mark, Гц | space, Гц |
|------|----------|-----------|
| 1    | 1200     | 2200      |
| 2    | 3000     | 4000      |
| 3    | 1500     | 2600      |
| 4    | 3400     | 4300      |

OFDM-данные у пар занимают разнесённые поднесущие, FSK-канал
управления не пересекается.



Файлы уже лежат в `app/files_to_send/`: `test_1B.txt` (1 Б),
`test_2B.txt` (2 Б), `test_20KB.txt` (20 КБ). В меню п.1 они
выбираются номером из списка.

1. **30 см, тихо.** Приёмник: п.2. Передатчик: п.1, `test_1B.txt`.
   Ожидание: режим 64QAM/16QAM, ~1–2 с, MD5 OK. Повторить `test_2B.txt`.
2. **Макс. дистанция, тихо.** Разнести ноутбуки на 3–5 м. Стартовый
   SNR ниже → режим QPSK. Передать `test_1B.txt`, `test_2B.txt`. MD5 OK.
3. **Макс. дистанция, больший файл.** То же расстояние, `test_20KB.txt`.
   Видно прогресс-бар и скорость; ретрансы единичные. MD5 OK.
4. **Макс. дистанция + сильный шум.** Включить шум (музыка/фен).
   На видео: стартовый SNR низкий → режим FSK; при нарастании шума
   срабатывает пробник/fallback — видно строки «понижаю до FSK»,
   передача всё равно доходит. MD5 OK.
5. **Несколько пар одновременно (<= 1 м).** Два передатчика и два
   приёмника, пара 1 и пара 2 (разные тоны). Оба файла доходят,
   взаимных сбоев нет (Goertzel-детектор узкополосный).

Для записи видео удобно: `python app/modem.py > log.txt 2>&1` на обеих
сторонах + съёмка экрана; прогресс-бары и строки адаптации читаются
покадрово.

## Проверено в loopback (без железа)

| SNR        | Старт   | Финиш | Итог            |
|------------|---------|-------|-----------------|
| 35 дБ      | 64QAM   | 64QAM | match, 0 ретр.  |
| 15 дБ      | QPSK    | QPSK  | match, 0 ретр.  |
| 5 дБ       | FSK     | FSK   | match, 0 ретр.  |
| 30→8 дБ*   | 64QAM   | FSK   | match, 18 ретр. |

*динамическая деградация канала посреди передачи — сработала
fallback-цепочка 64QAM→16QAM→QPSK→FSK, файл дошёл целиком.

## Файлы

- `app/modem.py` — приложение целиком (меню, TX, RX, протокол).
- `labs/common/modem_lib.py` — DSP-библиотека из лаб (FSK/OFDM/RS/CRC).
- `app/files_to_send/` — файлы на отправку (test_1B/test_2B/test_20KB
  — по заданию хакатона; свои txt кладите сюда же).
- `app/received/` — сюда падают принятые файлы.
