### 💡 Ключевая стратегия: МНОГОРЕЖИМНОСТЬ — наше секретное оружие

Вместо одного режима делаем **три режима**, которые автоматически выбираются под условия:

| Режим | Модуляция | Скорость | Дальность | Когда использовать |
|-------|-----------|----------|-----------|-------------------|
| 🐢 **Reliable** | BFSK (2 тона) | 50-100 бит/с | до 20 м | Шум, далеко, плохие условия |
| 🚶 **Medium** | MFSK (8 тонов) | 200-400 бит/с | до 10 м | Средние условия |
| 🚀 **Turbo** | OFDM (512 несущих) | 1-80 кбит/с | до 5 м | Тишина, близко, кабель |

**Почему это победа:** Ни у кого из конкурентов не будет адаптивного переключения между FSK и OFDM. Это показывает глубину понимания и инженерную культуру.


## 🔧 ЧТО ПОПРОБОВАТЬ И ПРОВЕРИТЬ (ЭКСПЕРИМЕНТЫ)

### Гипотеза 1: Goertzel vs FFT для демодуляции FSK
**Что проверить**: Goertzel алгоритм быстрее FFT в 5-10 раз для детекции 2 тонов  
**Как проверить**: Замерить `timeit` для Goertzel и `np.fft.rfft` на одинаковых данных  
**Источник**: [airmodem использует Goertzel](https://github.com/TheBushBoy/airmodem) для детекции на ESP32  
**Ожидание**: Goertzel выигрывает при малом числе частот

### Гипотеза 2: Chirp correlation даёт точную синхронизацию
**Что проверить**: Корреляция с chirp-шаблоном даёт точность ±1 сэмпл  
**Как проверить**: Сгенерировать chirp, пропустить через канал, измерить положение пика  
**Источник**: [SonicTag использует chirp sync](https://github.com/Jillou35/SonicTag), [OFDM modem part 2](https://hardwareteams.com/docs/dsp/audio-ofdm/audio-ofdm-modem-part2/)  
**Ожидание**: Пик корреляции > 0.8 при SNR > 0 дБ

### Гипотеза 3: Reed-Solomon даёт выигрыш 3-5 дБ
**Что проверить**: BER(SNR) c RS и без  
**Как проверить**: `add_noise` при разных SNR, `ber_measure`  
**Источник**: [ByteWaves](https://github.com/tacio/bytewaves) использует RS(255,223) с 16 ecc bytes  
**Ожидание**: На BER=10⁻³ RS даёт выигрыш ~3 дБ

### Гипотеза 4: OFDM с CP эффективнее FSK по скорости
**Что проверить**: OFDM даёт на порядок больше бит/с в той же полосе  
**Как проверить**: Сравнить скорость передачи для FSK и OFDM  
**Источник**: [amodem](https://github.com/romanz/amodem) достигает 80 кбит/с через OFDM  
**Ожидание**: OFDM в 10-100 раз быстрее FSK

### Гипотеза 5: LMS эквалайзер улучшает BER
**Что проверить**: Адаптивный эквалайзер компенсирует искажения динамика  
**Как проверить**: Передать через реальный канал, измерить BER с и без эквалайзера  
**Источник**: [ByteWaves](https://github.com/tacio/bytewaves) использует LMS equalization  
**Ожидание**: Улучшение BER в 2-3 раза в сложных условиях

### Гипотеза 6: CPFSK лучше стандартного FSK
**Что проверить**: Continuous-phase FSK даёт меньше спектральных выбросов  
**Как проверить**: Сравнить спектрограмму FSK и CPFSK  
**Источник**: [DHWANI](https://github.com/neha23jk/DHWANI) использует CPFSK  
**Ожидание**: CPFSK спектр уже на 20-30%

### Гипотеза 7: Адаптивный режим работает лучше любого одного режима
**Что проверить**: Auto-switching FSK/OFDM по SNR даёт лучший компромисс  
**Как проверить**: Измерить время передачи файла при разных SNR с адаптацией и без  
**Ожидание**: Адаптация всегда даёт минимальное время при заданном BER

## 🎯 ЧТО ДЕЛАЕТ НАШЕ РЕШЕНИЕ ПОБЕДНЫМ

### 1. Многорежимность
Мы не привязаны к одному типу модуляции. FSK для надёжности, OFDM для скорости, адаптивный выбор между ними.

### 2. Полный стек FEC
Reed-Solomon + convolutional code + interleaving + soft Viterbi (как в [weaklink-modem](https://pypi.org/project/weaklink-modem/)). Это даёт работу в условиях, где другие модемы падают.

### 3. ARQ протокол
Stop-and-Wait + Go-Back-N с адаптивным таймаутом. Гарантия доставки 100%.

### 4. Инженерная культура
- Модульная архитектура (каждый блок отдельно)
- Тесты (unit + integration + loopback)
- Документация (README, архитектура, протокол)
- Git (чистые коммиты, CI/CD)

### 5. Научный подход
Каждая гипотеза проверяется экспериментом. Результаты тестов документируются. Спектрограммы, графики BER, таблицы.

### 6. UX
- CLI с прогресс-баром
- Web UI для демонстрации (Flask + WebSocket)
- Режимы: send / recv / test / calibrate
